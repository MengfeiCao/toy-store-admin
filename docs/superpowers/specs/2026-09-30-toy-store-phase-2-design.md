# 玩具店管理后台第二阶段设计规格

## 1. 背景与目标

现有 MVP 已经打通商品、入库、库存、客户、销售订单、整单出库、二态收款和基础经营概览。第二阶段在保留现有业务规则的基础上，补齐采购、可靠库存、售后、经营报表和门店快速操作能力。

本阶段仍服务单门店、单仓库，目标是形成下面的完整经营闭环：

```text
供应商 → 采购单 → 分批到货 → 库存
                              ↓
客户 → 扫码开单 → 销售出库 → 收款 → 退货/换货/退款
                              ↓
盘点/报损/调整 → 库存流水 → 日报/月报/商品分析/Excel
```

所有新增功能按可独立验收的小阶段交付，每个任务完成后执行自检、相关测试、构建检查和 Git 差异检查，再提交独立版本并继续下一项。

## 2. 已确认的业务边界

- 单门店、单仓库，不设计门店或仓库调拨。
- 销售没有折扣或优惠金额，商品是多少就是多少。
- 销售收款仍只有未收款和已收款，不支持部分收款。
- 采购付款仍只有未付款和已付清，不支持分期付款。
- 已付款订单允许因部分退货产生部分退款；部分退款不改变原订单的已收款状态。
- 一张订单可以按商品和数量部分退货或换货，累计数量不能超过原出库数量。
- 换货仅支持同款、同数量，不补收或退还差价。
- 退回商品必须选择完好入库或损坏报损。
- 售后只从已出库订单发起；未出库订单继续通过编辑或取消处理。
- 跨月退货和退款计入实际发生售后的月份。
- 店员可以直接处理采购入库、库存调整和退款，无需管理员审批。
- 扫码设备为 USB 扫码枪；打印使用 80 毫米热敏小票打印机。
- 每个商品第一版保留一张主图。
- 滞销商品定义为最近 30 天没有销售且当前库存大于零的商品。

## 3. 实施分期

### 3.1 第 2.0 阶段：现有 UI 统一

检查现有登录、首页、商品、入库、库存流水、客户、销售订单和用户管理页面。有 Ant Design 对应组件的原生按钮、输入框、选择框、表格、弹窗、确认提示和文件上传统一替换为 Ant Design，同时保持现有业务行为不变。

普通标题、文字和布局容器继续使用合适的 HTML 元素，不为组件化而过度改造。

### 3.2 第 2.1 阶段：商品、采购和库存基础

- 商品条码、单张主图和库存预警值。
- 供应商资料、采购单、采购明细和采购价格。
- 采购单分批到货、每批采购入库和到货进度。
- 采购单未付款、已付清和一次性付款记录。
- 库存盘点、盘盈、盘亏、报损和人工调整。
- 当前库存、库存流水和低库存预警。

### 3.3 第 2.2 阶段：售后管理

- 从已出库销售订单创建售后单。
- 按商品和数量部分退货。
- 已付款订单按原售价生成部分退款记录。
- 未付款订单按扣除退货后的净额一次性收款。
- 完好商品恢复可售库存，损坏或拆封商品生成报损流水。
- 同款、同数量换货及替换商品再次出库。

### 3.4 第 2.3 阶段：报表和门店效率

- 日报、月报、商品分析、库存分析、采购分析和售后分析。
- ECharts 图表、对应明细表格和 Excel 导出。
- 扫码枪快速识别商品、重复扫码累计数量和快速开单。
- 80 毫米热敏小票打印与重新打印。

## 4. 页面与导航

新增及调整后的导航结构如下：

```text
采购管理
├─ 供应商
├─ 采购单
└─ 采购入库

库存管理
├─ 当前库存
├─ 库存流水
├─ 库存盘点
├─ 库存调整
└─ 库存预警

销售管理
├─ 销售订单
├─ 快速开单
└─ 售后管理

经营报表
├─ 销售日报
├─ 销售月报
├─ 商品分析
└─ 数据导出
```

采购、库存和售后页面允许管理员与店员访问。店员可以看到完成采购和退款操作所需的单据金额；现有成本和毛利润经营权限保持不变，面向店员的经营报表不返回毛利润数据。

## 5. UI 与交互规范

项目继续使用 Ant Design。存在合适组件时禁止使用外观和交互不一致的原生表单控件。

| 场景 | 组件 |
|---|---|
| 列表、分页、状态 | `Table`、`Pagination`、`Tag` |
| 搜索与筛选 | `Form`、`Input`、`Select`、`DatePicker` |
| 数量与金额 | `InputNumber` |
| 新建和编辑 | `Modal` 或 `Drawer` |
| 图片上传与预览 | `Upload`、`Image` |
| 操作确认 | `Popconfirm` 或 `Modal.confirm` |
| 结果反馈 | `message` 或 `notification` |
| 业务进度 | `Steps`、`Progress` |
| 数据概览 | `Card`、`Statistic` |
| 空数据 | `Empty` |

商品图片上传必须显示上传进度、成功预览和失败提示。快速开单页面收到扫码枪输入后自动查找商品并加入订单，重复扫描同一条码时增加数量。扫描不到商品或库存不足时显示明确提示。

经营报表统一使用 ECharts。趋势使用折线图或柱状图，商品排行使用柱状图。图表、表格和 Excel 使用同一份统计结果，不分别计算。

80 毫米打印页面只保留店铺、订单、商品、数量、单价、合计、收款方式和时间等小票内容，不显示后台菜单或操作按钮。打印失败不回滚已经完成的订单或出库，并允许重新打印。

## 6. 数据模型

### 6.1 商品扩展

在 `products` 中确认或增加：

- `barcode text unique nullable`：扫码枪识别码。
- `image_path text nullable`：单张商品主图。
- `low_stock_threshold integer nullable`：库存预警值。

条码非空时必须唯一。采购和销售单据继续保存当时的价格或成本快照，后续修改商品资料不影响历史数据。

### 6.2 供应商与采购

#### suppliers

- 名称、联系人、电话、地址、备注、状态。
- 创建人、创建时间和更新时间。

#### purchase_orders

- 采购单号、供应商、状态、总金额和备注。
- 付款状态、付清时间和操作人。
- 创建、确认和完成的人员与时间。

状态为 `draft`、`confirmed`、`partially_received`、`completed` 和 `cancelled`。付款状态为 `unpaid` 和 `paid`。

#### purchase_order_items

- 商品、采购数量、采购单价、已到货数量。
- 商品名称、货号和采购价格快照。

#### purchase_receipts / purchase_receipt_items

一张采购单可以有多张到货单。每张到货单记录本次实际到货商品和数量、操作人及时间。累计到货数量不能超过采购数量。

#### supplier_payments

采购单一次性付清时生成一条付款记录。已付清采购单不能重复付款。本阶段不支持分期付款、预付款或供应商对账。

### 6.3 盘点与库存调整

#### stock_counts / stock_count_items

盘点单保存盘点状态、日期和操作人；明细保存商品、账面数量、实际数量和差异数量。确认盘点后不可修改，并根据差异生成库存调整与库存流水。

#### stock_adjustments / stock_adjustment_items

调整类型包含盘盈、盘亏、报损和人工调整。每条明细记录调整前数量、变化数量、调整后数量、原因和来源单据。

现有 `stock_records` 扩展来源类型和来源标识，用同一张流水表承载采购到货、销售出库、退货入库、换货出库、盘盈、盘亏和报损。每条业务明细只能生成一次对应流水。

### 6.4 售后与退款

#### after_sales_orders

- 售后单号、原销售订单、类型、状态、备注。
- 创建和完成的操作人与时间。

类型为退货或换货。售后仅能关联已出库订单。

#### after_sales_items

- 原销售明细、处理数量、原售价和原成本快照。
- 商品状况为完好或损坏。
- 处理结果为恢复库存、报损或换货发出。

#### refunds

- 售后单、销售订单、退款金额、退款时间和操作人。

部分退款金额等于退货数量乘以原销售单价。原订单保持已收款，并派生累计退款和实收净额。未收款订单发生退货后不生成退款记录，待收金额等于原订单金额减去已确认退货金额。

换货必须是同一原销售明细对应的商品和相同数量。退回商品先按完好或损坏处理，再生成同款商品负向库存流水。可售库存不足时整项换货失败。

## 7. 核心业务流程

### 7.1 采购与分批到货

```text
创建采购草稿 → 添加商品、数量和采购价 → 确认采购
→ 登记一次到货 → 增加库存并生成流水
→ 继续登记到货 → 全部到齐后自动完成
→ 一次性标记已付清
```

每次到货都在一个数据库事务内锁定采购单及相关商品，校验采购状态和剩余未到数量，再写入到货单、增加库存、更新累计到货数量并生成流水。任一环节失败时全部回滚。

到货确认后，商品当前成本更新为本次采购明细的采购单价。系统继续采用“当前成本”方案，不引入移动平均成本；后续销售出库保存当时的商品成本快照。

### 7.2 盘点与调整

```text
创建盘点单 → 带出账面库存 → 输入实际数量
→ 查看差异 → 确认盘点 → 调整库存并生成流水
```

盘点确认时重新读取并锁定当前库存。如果账面库存从创建盘点单后已经变化，必须提示用户刷新差异后再确认，不能使用过期数量覆盖库存。

### 7.3 退货退款

```text
选择已出库订单 → 选择商品与数量 → 选择完好或损坏
→ 确认退货 → 恢复库存或报损 → 必要时生成退款
```

确认前重新计算原订单各商品的可退数量。累计已退和已换数量不能超过原出库数量。跨月售后按完成售后的日期进入报表。

### 7.4 同款换货

```text
选择已出库订单 → 选择同款商品与数量 → 登记退回状况
→ 恢复库存或报损 → 校验可售库存 → 同款再次出库
```

换货不修改订单金额且不产生退款。退回处理与替换品出库必须在同一事务中完成。

### 7.5 快速开单

```text
扫描条码 → 查找商品 → 加入订单或累计数量
→ 选择客户或散客 → 直接确认或保存草稿
→ 确认出库 → 打印小票
```

快速开单沿用现有销售订单价格、库存、确认、出库和收款规则，不建立第二套订单逻辑。

## 8. 报表口径

本阶段不保存独立日报或月报结果表。报表从销售、采购、售后和库存流水按筛选条件计算。

```text
净销售额 = 已出库销售额 - 已确认退款额
净销售成本 = 原销售出库成本 + 换货再次出库成本 - 完好退货恢复库存的成本
净毛利润 = 净销售额 - 净销售成本
```

损坏或拆封退货不恢复库存，因此不冲减销售成本，并在报损统计中单独展示。换货不改变销售额；换出的新商品增加销售成本，完好退回商品冲减成本，损坏退回商品不冲减成本。

主要报表包括：

- 销售日报：销售额、退款额、净销售额、销售成本、净毛利润和订单数。
- 销售月报：按天展示上述指标和当月汇总。
- 商品分析：销量、销售额、毛利润排行，以及 30 天滞销商品。
- 库存分析：当前库存数量与金额、低库存和报损统计。
- 采购分析：采购金额、到货数量和未付款采购单。
- 售后分析：退货数量、退款金额、换货数量和报损数量。

店员报表不返回销售成本和毛利润。Excel 导出使用与当前页面完全相同的筛选条件、权限和统计口径。

## 9. 原子性、并发与幂等

- 采购到货、销售出库、退货、换货、盘点和库存调整均通过受保护的 PostgreSQL 函数完成。
- 单次操作中的业务单据、库存数量和库存流水同时成功或同时失败。
- 关键函数锁定单据和受影响的商品记录，在锁内重新检查状态、数量和库存。
- 已完成业务再次提交时不得重复改变库存、付款或退款。
- 前端提交期间禁用关键按钮；超时后先重新查询单据状态，再决定是否允许重试。
- 库存不能为负数，累计到货量不能超过采购量，累计退换量不能超过原出库量。
- 已确认或已完成单据不直接删除，通过取消、调整或售后流程纠正。

## 10. 权限与审计

- 管理员和店员都可处理供应商、采购、到货、盘点、调整和售后。
- 用户管理、商品停用以及现有管理员专属操作继续保持原权限。
- 店员可查看完成采购和售后操作需要的单据价格，但经营报表不返回成本与毛利润。
- 所有关键操作保存操作人和操作时间。
- 行级安全策略和数据库函数共同校验身份与业务权限，不能只依赖隐藏前端按钮。

## 11. 错误处理

- 必填字段、正整数、金额、唯一条码和业务状态在前端与数据库分别校验。
- 超额到货、库存不足、超额退换、重复付款或重复退款返回具体业务原因。
- 表单错误显示在对应字段附近，业务结果使用 Ant Design 的提示组件。
- 图片上传校验格式和大小，失败可重试且不破坏商品其他资料。
- 报表无数据时展示空状态；导出或打印失败不修改业务数据。
- 技术日志保留单据号和错误上下文，用户界面不直接展示数据库异常文本。

- 当前技术栈、目录结构和常用验证命令。
- 单门店、单仓库、无折扣、销售二态收款和采购一次性付款等业务规则。
- Ant Design 组件优先与 ECharts 报表规范。
- 数据库迁移、原子事务、权限和价格快照要求。
- 精准修改、禁止无关重构、任务级自检和独立 Git 提交要求。

5. 涉及交互时在浏览器完成实际操作。
6. 检查 Git 差异后提交独立版本。

### 13.2 第 2.0 阶段

- 现有页面可由 Ant Design 替代的原生交互控件已经替换。
- 商品图片使用 `Upload` 上传并可预览。
- 登录、商品、客户、入库、销售、收款和用户管理行为没有退化。

### 13.3 第 2.1 阶段

- 可维护供应商、商品条码、单张主图和库存预警值。

## 14. 本阶段明确不做

- 多门店、多仓库和库存调拨。
- 不同商品换货、换货补款或退差价。
- 销售折扣、优惠金额和复杂促销。
- 销售订单部分收款。
- 采购分期付款、预付款和完整供应商对账。
- 手机或摄像头扫码。
- 完整会计、发票和复杂审批。
- 多张商品图、图片编辑或图片识别。
