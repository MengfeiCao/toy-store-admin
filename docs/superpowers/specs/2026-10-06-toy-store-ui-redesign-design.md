# 玩具销售后台 UI 改版设计说明

## 设计判断

这是一个供店主和店员高频使用的桌面端零售业务后台。界面应优先保证扫描、筛选、录单和核对数据的效率，视觉语言采用“清晰、稳定、轻零售感”，而不是展示型网站常用的大留白、强动效或装饰性布局。

## 设计假设

- 主要使用环境是 1366px 及以上的桌面浏览器。
- 现有 React、Ant Design 和业务流程保持不变。
- 蓝色继续作为品牌与主操作色，深海军蓝继续用于侧栏。
- 中文界面优先使用系统中文字体，不额外引入在线字体资源。
- 第一轮只建立设计基础并改造“玩具管理”作为样板页；其余页面在样板确认后统一迁移。
- 移动端只保证基本可访问，不在第一轮重做完整移动导航。

## 当前审查结论

### 1. 组件语言不统一

`ProductListPage` 同时使用原生 `button`、`input`、`select`、自定义状态标签和 Ant Design `Table`、`Tag`。采购、销售等页面则主要使用 Ant Design 组件，同一套后台出现不同的控件高度、边框、焦点态和交互反馈。

### 2. 缺少统一主题入口

应用没有 `ConfigProvider` 主题配置，品牌蓝、背景色、文字色、圆角和阴影散落在 `styles.css` 中。Ant Design 组件使用默认主题，自定义区域使用另一套硬编码颜色，因此无法通过一次修改统一全站。

### 3. 页面宽度和信息密度缺少规则

`.feature-page` 固定最大宽度为 1120px，并且没有居中。在大屏上右侧留白较多，列数较多的业务表格又容易出现横向滚动。工具栏宽度也由每个页面各自决定。

### 4. 状态表达不一致

商品状态使用自定义 `status-pill`，库存、采购、销售状态使用 Ant Design `Tag`，错误状态有时用 `Alert`、有时用普通段落。相同含义没有稳定的颜色和组件规范。

### 5. 加载、空数据和错误状态不完整

大部分表格依赖默认 loading 和空文本，经营概览使用普通文字显示加载。空列表没有下一步操作提示，错误提示的视觉等级也不一致。

### 6. 可访问性细节不足

自定义按钮和导航没有统一的 `:focus-visible` 样式，页面没有“跳到主要内容”入口。键盘用户可以操作大部分表单，但焦点反馈不稳定。

### 7. 视觉层级偏模板化

页面标题、说明、筛选区和表格之间已有基本层次，但标题尺寸、段落宽度、卡片边界和数字排版没有统一规则。经营概览自定义卡片与经营报表的 Ant Design 卡片也不一致。

## 采用的设计方向

### 色彩

- 品牌主色：`#2563EB`
- 深色侧栏：`#172238`
- 页面背景：`#F6F8FB`
- 主文字：`#182230`
- 次要文字：`#667085`
- 分隔线：`#E4E7EC`
- 成功：`#178A55`
- 警告：`#B54708`
- 危险：`#D92D20`

颜色只用于品牌、状态和操作优先级，不添加渐变、霓虹或大面积装饰背景。

### 字体与数字

- 中文与正文：`"PingFang SC", "Microsoft YaHei", system-ui, sans-serif`
- 英文与数字沿用系统字体。
- 金额、库存和报表数字启用 `font-variant-numeric: tabular-nums`。
- 页面标题保持清晰但不过度放大；后台不采用营销站式大标题。

### 布局

- 保留左侧导航和独立滚动行为。
- 内容区域最大宽度调整到 1440px 并居中。
- 页面标题、工具栏、提示、表格之间使用固定的纵向间距节奏。
- 数据页维持较高信息密度，表格行高不做大幅增加。

### 组件

- 表单、按钮、筛选、状态、提示统一优先使用 Ant Design。
- 自定义 CSS 只负责应用外壳、品牌区和无法由主题令牌覆盖的布局。
- 主操作使用实体按钮，次操作使用普通按钮，行内操作使用链接按钮。
- 状态统一使用 `Tag`，并建立稳定的语义颜色映射。

### 动效

- 只保留 120–200ms 的 hover、focus 和弹层过渡。
- 不添加滚动入场、视差、悬浮跟随、纹理动画或页面级转场。
- 尊重 `prefers-reduced-motion`。

## 明确不采用的第三方技能建议

- 不移除左侧导航；它适合当前多模块后台的信息架构。
- 不使用不对称破格布局、重叠卡片或大面积留白。
- 不加入背景图片、噪点纹理或玻璃拟态。
- 不为了字体特色引入中文覆盖不足的在线字体。
- 不把所有内容都改成卡片，也不为简单操作增加新的弹窗。

## 第一轮范围

1. 建立 Ant Design 全局主题和对应 CSS 变量。
2. 统一应用外壳、内容宽度、焦点态与数字排版。
3. 把“玩具管理”改造成样板页，统一搜索、状态筛选、按钮、状态标签和错误提示。
4. 保证现有商品图片预览、库存表头筛选、角色权限和编辑逻辑不变。
5. 通过单元测试、完整测试、生产构建以及 1366px/1440px 视觉检查。

## 第一轮不包含

- 不修改数据库、接口或权限模型。
- 不改动采购、销售、库存和报表页面的业务实现。
- 不引入新的组件库、图标库、字体包或动画库。
- 不新增侧栏折叠、暗色模式、主题切换或移动端抽屉导航。
- 不调整业务文案和页面路由。

## 验收标准

- Ant Design 与自定义外壳共享同一组品牌色、圆角、字体和背景基线。
- 玩具管理页不再使用原生输入框、下拉框和按钮。
- 玩具管理的图片预览、库存状态表头筛选、编辑、启停和角色权限测试继续通过。
- 左侧菜单仍然只滚动菜单区域，账户区固定在底部。
- 所有自定义交互元素都有清晰的键盘焦点态。
- 1366px 宽度下页面不出现非必要的整体横向滚动。
- `npm test -- --run`、`npm run build` 和相关本地 E2E 流程通过。

## 后续迁移顺序

样板页确认后，按“采购列表 → 销售列表 → 库存列表 → 表单与抽屉 → 经营概览与报表 → 登录页”的顺序迁移，每一组单独测试并提交，避免一次性全站重写。
