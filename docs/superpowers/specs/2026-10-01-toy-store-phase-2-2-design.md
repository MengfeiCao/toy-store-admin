# 玩具店后台 2.2 售后管理设计

## 目标与成功标准

在不改变原销售订单金额和已收款状态的前提下，为已完成出库的订单提供部分退货和同款换货。数据库原子校验累计可售后数量、库存和请求幂等；前端可从销售详情发起并查询历史售后。

成功标准：

- 累计退货与换货数量不超过原出库数量。
- 完好退回恢复库存，损坏退回不进入可售库存并可在售后分析中识别。
- 已收款退货按原售价生成一笔退款；未收款退货不生成退款，待收净额相应减少。
- 同款换货不改变销售额或生成退款，退回处理与替换品出库同一事务完成；库存不足整单回滚。
- 请求 UUID 重放不重复修改库存或生成退款。
- 店主和店员均可办理；成本快照不暴露给店员。

## 方案选择

采用“直接确认型售后单”：页面填写后一次提交，数据库直接生成已完成售后单。相比引入草稿、审批和多阶段状态，代码和状态更少，且符合已确认的“店员无需审批”边界。后续如确需审批，再以向前迁移扩展状态。

损坏退回不写可售库存变化；报损数量直接从售后明细统计，避免为了制造流水而先加库存再扣库存。换货完好品先回库再扣出同款，损坏品不回库，随后校验并扣出替换品。

## 数据与接口

- `after_sales_orders`：请求 UUID、售后单号、原销售单、退货/换货类型、完成状态、备注、操作人与时间、请求载荷。
- `after_sales_items`：原销售明细、商品与价格/成本快照、处理数量、完好/损坏状况。
- `refunds`：退货售后、原销售单、退款金额、操作人与时间，每张售后最多一条。
- `stock_records` 增加售后明细与动作；完好退回记 `return_in`，换货发出记 `exchange_out`。
- `post_after_sales`：锁定销售单、商品和既有售后明细，完成累计数量、库存、退款和幂等校验。
- `list_after_sales`、`get_after_sales`：列表和详情；店员返回业务所需售价与退款，不返回成本。
- `get_sales_order` 增加明细 ID、已售后数量、可售后数量、累计退款和待收净额。

## 页面

- 销售订单详情在已完成状态显示“办理售后”。
- 新建售后页选择退货/换货、数量、商品状况和备注，实时显示退款金额或换货说明。
- 售后列表展示单号、原订单、客户、类型、数量、退款额和完成时间；详情展示商品处理结果。
- 导航在销售分组增加“售后管理”。

## 验证

pgTAP 覆盖完好/损坏退货、已付/未付、换货、超量、库存不足、幂等和权限；Vitest 覆盖 API 映射及表单；Playwright 覆盖已付款部分退货和换货库存闭环。
